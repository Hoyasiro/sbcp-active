## 0. 먼저 읽을 것 (요약)

1. **학원 PC 한 대에서 쓰는 로컬 프로그램**입니다. 서버·인터넷 배포 없음. 데이터는 브라우저 localStorage + JSON 백업 파일.
2. **이 저장소는 공개(public)입니다.** 학생 이름·출결 데이터·백업 파일·API 키를 **절대 커밋하지 마세요.** (9절)
3. 저장 키 `STORAGE_KEY = 'acad-atd-03_1.4'` 는 **바꾸면 안 됩니다.** 바꾸면 학원 PC의 기존 출결 데이터를 못 읽습니다.
4. main은 **v1.9**(PR #4 병합), 최신 작업은 **v2.1**(브랜치 `claude/admiring-feynman-o0bmeu`, 미병합)입니다. (2절)
5. 설치·업데이트 파일(.exe)은 **실제 Windows에서 아직 실행 검증되지 않았습니다.** (7절)

## 4. 아키텍처

### 4-1. 동작 방식
- **단일 HTML 앱.** 배포물은 `index.html + css + js`를 한 파일로 합친 `SBCP.html` (build.py). 브라우저로 `file://` 실행.
- **AI 호출:** 브라우저에서 Gemini를 **직접** 호출 (`callReportApi()`). Gemini는 `Origin: null`(로컬 파일) 요청을 CORS 허용함을 확인함.
  - 엔드포인트 `https://generativelanguage.googleapis.com/v1beta/interactions`, 모델 `models/gemini-3-flash-preview`, 헤더 `x-goog-api-key`, `thinking_level: low`, 타임아웃 25초
  - 톤 3종: `parent`(학부모), `student`(학생), `peer`(지난주 보드 공개용 — 비교·질책 금지)
  - 키는 설정 → AI 연결에서 등록 → `acad-gemini-key` (출결 DB와 분리 → **백업 파일에 안 들어감**)
- **데이터:** 브라우저 localStorage. 크롬·엣지는 모든 `file://` 페이지가 저장소를 공유하므로 설치 위치가 바뀌어도 같은 브라우저면 데이터 유지. **브라우저가 다르면 데이터도 다름.**

## 5. 개발 · 검증 · 릴리즈

### 5-1. 필요한 도구
- Python 3 + `pip install markdown pillow`
- NSIS (`sudo apt install nsis`) — 설치 파일 빌드
- 검증용: Playwright + Chromium (클라우드 환경엔 `/opt/node22/lib/node_modules/playwright`, 브라우저 `/opt/pw-browsers`)
- 한글 글꼴 `fonts-noto-cjk`, 이모지 `fonts-noto-color-emoji` (스크린샷·포스터 렌더링 시)

### 5-2. 개발 중 확인
- `index.html`을 브라우저로 바로 열면 됨 (css/js 폴더를 읽음).
- **주의:** 같은 브라우저로 열면 실제 데이터와 저장소를 공유. 테스트는 별도 크롬 프로필이나 Playwright로.
- 레포에 자동 테스트는 없습니다. 지금까지는 Playwright 스크립트로 아래를 매번 확인했습니다 — 같은 수준을 유지하세요.
  - 등원·하원·하원 취소·등원 취소·실행취소 시 통계 수치 (월간 일수, 체류 분, 연속, 신기록)
  - 휴원일 연속 계산 (예: 수요일 휴원 → 화·목 연속)
  - 화면 맞춤: 1600×900 / 1920×1080 / 1920×945 / 1366×768 / **3160×1680** 에서 스크롤·잘림 없음, 보드 문장 "…" 없음, 원생 명단 잘림·"…" 없음
  - 보드: 4초 순환, ❚❚ 10초 자동 재생, ‹ › 이동, 드롭다운 고정 20초 해제
  - **버튼을 누른 뒤 번호 입력칸 포커스 복귀** (팝업 '확인', '취소하기', 보드 버튼) — 회귀가 잦았던 부분
  - 백업·복구 오류 처리 (CSV 선택, 손상 JSON, 같은 파일 재선택, BOM)
  - 실제 Gemini 연결 (클라우드 환경에선 프록시가 `x-goog-api-key`를 붙여 줌 — 테스트 시 임의 키 문자열로 동작)
- 시계를 고정해 테스트할 때는 `page.clock.install()` (지난주 = 기준일이 속한 주의 전 주 월~금).

### 5-3. 릴리즈 절차
1. `js/main.js`: `APP_VERSION` 올리기 (예: `'Acad-atd-03_1.8 (Desktop)'`), `WHATS_NEW`(업데이트 알림 문구) 수정
2. `index.html`: `<title>` 과 사이드바 하단 `Desktop Edition v1.8` 수정
3. `docs/사용설명서.md` 버전 표기, `README.md` 변경 사항·개발 로그
4. `python3 tools/build.py` → `release/SBCP_Setup_v1.8.exe`, `release/SBCP_Update_v1.8.exe`
5. 이미 설치된 PC에는 **Update 파일만** 전달 → 실행 후 F5, 첫 실행 시 "v1.8 업데이트가 적용되었습니다" 알림
6. 커밋·푸시. **PR은 사용자가 요청할 때만** 만든다.

### 5-4. 설치·업데이트 파일 동작
- 관리자 권한 없이 `%LOCALAPPDATA%\SBCP`에 설치, 레지스트리 `HKCU\Software\SBCP` (`InstallDir`, `Browser`)
- 크롬·엣지가 둘 다 있으면 "어떤 브라우저로 열까요?" 질문 → 기억 (데이터가 브라우저별이라 예전 브라우저를 골라야 함)
- 바로가기(바탕화면·시작 메뉴·시작프로그램)는 `브라우저 --start-fullscreen "SBCP.html"`
- 업데이트 파일은 `SBCP.html`·사용설명서만 교체하고, **이미 있는** 바로가기만 새 방식으로 다시 만듦
- 전체 화면 옵션이 무시되는 경우(브라우저가 이미 백그라운드 실행 중) → 앱이 첫 키 입력·클릭 때 Fullscreen API로 전환

## 6. 운영 지식

- **13:30~14:00에 프로그램 화면이 열려 있어야** 지난주 리포트가 자동 생성됩니다. PC 절전 금지(사용설명서 3절).
- 생성 전 등원한 학생은 그날 팝업에 통계만, 다음 등원부터 AI 문장.
- 무료 Gemini 키는 분당 제한이 있음 → 학생 사이 7초 간격(40명 ≈ 5~10분). **429**(사용량 제한)·**503**(Google 혼잡)이 실제로 자주 관찰됨. 둘 다 앱 버그가 아니며, 14:00 재시도 또는 "미생성분 지금 생성" 버튼으로 채움.
- 지난주 출석 0일 학생은 AI를 호출하지 않고 보드 순환에서도 제외(응원 문구만).
- 백업 파일 `acad_backup_YYYY-MM-DD.json`. 복구는 데이터 관리 → 불러오기(파일 검사 후 요약 확인). 사용설명서 5절에 오류별 해결표.
- 휴원일을 바꾸면 전원 통계 재계산. 음력 공휴일·대체공휴일은 수동 등록.

## 8. 학생명단포스터제작 업무

출결 키오스크 옆에 붙이는 **A4 포스터형 PDF** (학생 이름 + 2자리 번호). 학생이 포스터에서 자기 번호를 찾아 입력하는 용도.

- 생성기: `tools/poster/make_poster.js` (Playwright Chromium으로 HTML → A4 PDF)
  ```bash
  node tools/poster/make_poster.js data/roster.json data/학생_코드_리스트-포스터형_YYYY-MM-DD.pdf
  ```
- 입력: `{"students":[{"no":"01","name":"..."}]}` 형식 JSON 또는 **출결 앱 백업 JSON 그대로**. 형식 예시는 `tools/poster/roster.example.json`(**가상 이름**).
- 규칙: 번호(`int(no)`) 순 정렬, **결번은 채우지 않고** 다음 번호를 이어 붙임, 4열 × 열당 12명, 두 글자 이름은 가운데 띄움(세 글자와 폭 맞춤).
- 디자인: 헤더 그라디언트 `#06065f→#10108a`, 포인트 핑크 `#eb3192`, 틸 `#5ac5bf`, 이름 `#000060`, 배경 `#fafbfe`, 카드 높이 40px·배지 33×25px. 원래 WeasyPrint로 만들던 포스터와 나란히 비교해 같은 모양임을 확인함.
- **실제 명단과 결과 PDF는 `data/`에만 두세요(gitignore).** 공개 저장소이므로 학생 이름을 커밋하지 않습니다. 새 세션에서는 사용자가 최신 명단(백업 JSON 또는 표)을 첨부해 줘야 합니다.
- 사용자는 보통 "52번 ○○○ 추가, 13번 퇴원"처럼 **변경분만** 알려 줍니다. 받은 최신 명단에 반영해 다시 생성하면 됩니다.
- 참고: 사용자가 처음 준 예시 PDF는 인계 문서(2026-10-06, 45명)보다 **이전 시점 명단(46명)**이었습니다. 날짜가 붙은 명단을 최신으로 보고 작업했고 사용자에게 알렸습니다.

## 10. 사용자와 일하는 방식 (지금까지의 합의)

- **한국어**로 소통. 비개발자 원장님 — 기술 용어는 풀어서, 결과·영향 중심으로 짧게.
- **미리보기 먼저:** 화면 변경은 스크린샷이나 단일 HTML 미리보기를 보여 줌. 레이아웃 변경처럼 취향이 갈리는 건 **"관문"** 방식 — 미리보기 브랜치에 커밋·푸시 → 사용자 "적용" 후 작업 브랜치에 합침.
- 작업 단위마다 커밋·푸시. **PR은 요청 시에만.**
- 오래 걸리는 질문 연쇄를 싫어함 → 합리적 기본값으로 진행하고 결과를 보고. 꼭 필요한 결정만 묻기.
- 할 수 없는 요청은 **어려운 항목과 이유를 나열**해 달라는 요청이 있었음. (예: 웹페이지 스스로 전체 화면 불가 → 바로가기 옵션 + 첫 입력 시 전환으로 우회)
- 테스트하지 못한 것은 반드시 "확인하지 못함"으로 명시.
